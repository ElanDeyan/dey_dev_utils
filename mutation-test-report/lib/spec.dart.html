       3 /// The Specification Pattern: compose business rules as reusable, testable predicates.
       4 ///
       5 /// A Spec represents a single business rule that an object either satisfies or doesn't.
       6 /// Instead of embedding validation logic directly in methods, specifications are
       7 /// first-class objects that can be created, combined, tested, and reused independently.
       8 ///
       9 /// This pattern is ideal for:
      10 /// - **Domain rules**: Entity validation, filtering, and search criteria
      11 /// - **Reusability**: The same rule applies in multiple contexts without duplication
      12 /// - **Testability**: Each rule is isolated and easy to unit test
      13 /// - **Composability**: Combine simple rules into complex business logic
      14 /// - **Readability**: Express business intent clearly through method names
      15 ///
      16 /// Compose specs using:
      17 /// - `&` / [and] — Both must be satisfied (AND logic)
      18 /// - `|` / [or] — At least one must be satisfied (OR logic)
      19 /// - `^` / [xor] — Exactly one must be satisfied, not both (XOR logic)
      20 /// - [nand] — At least one must not be satisfied (NAND logic)
      21 /// - [nor] — Neither must be satisfied (NOR logic)
      22 /// - [xnor] — Both must have the same satisfaction state (XNOR logic)
      23 /// - [toNegated] or `~` — Inverts the rule (NOT logic)
      24 ///
      25 /// AND, OR, NAND, and NOR use left-to-right short-circuit evaluation. XOR and
      26 /// XNOR evaluate both operands because both results are needed.
      27 ///
      28 /// **Creating a Spec:**
      29 /// ```dart
      30 /// /// Business rule: person is old enough to vote
      31 /// class IsEligibleVoter extends Spec<Person> {
      32 ///   @override
      33 ///   bool isSatisfiedBy(Person person) => person.age >= 18;
      34 /// }
      35 ///
      36 /// /// Business rule: person has valid contact info
      37 /// class HasValidEmail extends Spec<Person> {
      38 ///   @override
      39 ///   bool isSatisfiedBy(Person person) => person.email.contains('@');
      40 /// }
      41 /// ```
      42 ///
      43 /// **Using a Spec:**
      44 /// ```dart
      45 /// // Single rule
      46 /// final isVoter = IsEligibleVoter();
      47 /// if (isVoter.isSatisfiedBy(person)) {
      48 ///   registerToVote(person);
      49 /// }
      50 ///
      51 /// // Composed rules
      52 /// final validVoter = IsEligibleVoter() & HasValidEmail();
      53 /// final voters = people.where((p) => validVoter.isSatisfiedBy(p)).toList();
      54 ///
      55 /// // Complex compositions
      56 /// final canReceiveNewsletter = HasValidEmail() & (IsEligibleVoter() | HasOptedIn());
      57 /// ```
