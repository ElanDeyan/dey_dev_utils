       7 ///
       8 /// A [Monoid] captures a fundamental algebraic structure consisting of:
       9 /// - A type [T] representing the set of values
      10 /// - A binary operation [combine] that combines two values of type [T]
      11 /// - An identity element [empty] that doesn't change the result when combined
      12 ///
      13 /// **Monoid laws (assumed but not enforced):**
      14 /// 1. **Closure**: For any `a, b : T`, `combine(a, b) : T`
      15 ///    (combining two values produces another value of the same type)
      16 /// 2. **Associativity**: `combine(combine(a, b), c) == combine(a, combine(b, c))`
      17 ///    (the order of grouping doesn't matter, only the order of application)
      18 /// 3. **Identity**: `combine(empty, a) == a` and `combine(a, empty) == a`
      19 ///    (the empty element doesn't change anything when combined)
      20 ///
      21 /// These laws are assumed to be satisfied by all implementations.
      22 ///
      23 /// **Common examples:**
      24 /// - **Integers with addition**: empty = 0, combine = (a, b) => a + b
      25 /// - **Integers with multiplication**: empty = 1, combine = (a, b) => a * b
      26 /// - **Strings with concatenation**: empty = "", combine = (a, b) => a + b
      27 /// - **Lists with concatenation**: empty = [], combine = (a, b) => a + b
      28 /// - **Booleans (logical OR)**: empty = false, combine = (a, b) => a || b
      29 /// - **Booleans (logical AND)**: empty = true, combine = (a, b) => a && b
      30 /// - **Any type with min/max**: empty = max/min value, combine = (a, b) => min/max(a, b)
      31 ///
      32 /// **Use cases:**
      33 /// - **Aggregation and reduction**: Combine multiple values into a single result
      34 /// - **Parallel/distributed computation**: Combine partial results from independent computations
      35 /// - **Accumulation**: Build up a value by repeatedly combining increments
      36 /// - **Defaults and folding**: Safely reduce collections to a single value with predictable behavior
