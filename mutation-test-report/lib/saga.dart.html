      24 /// A saga: a sequence of async operations with automatic compensation on failure.
      25 ///
      26 /// A [Saga] implements the Saga pattern for managing distributed transactions
      27 /// in a local/in-process context. It executes a sequence of steps, each with
      28 /// an associated compensation (rollback) function.
      29 ///
      30 /// **Key properties:**
      31 /// - **Atomicity simulation**: Either all steps succeed, or all completed steps
      32 ///   are compensated (rolled back) on failure
      33 /// - **Compensation order**: Compensations execute in reverse order of step
      34 ///   execution (LIFO), like unwinding a stack
      35 /// - **Error recovery**: If any step fails, all prior compensations are executed
      36 ///   before rethrowing the original error
      37 /// - **Type safety**: Each [SagaStep<T>] maintains its own type information,
      38 ///   ensuring the return value type matches the compensation input type
      39 ///
      40 /// **Execution model:**
      41 /// 1. For each registered step:
      42 ///    - Execute the step (get result of type T)
      43 ///    - Register its compensation with the result
      44 ///    - If success, continue to next step
      45 /// 2. If any step throws:
      46 ///    - Execute all registered compensations in reverse order (LIFO)
      47 ///    - Rethrow the original error
      48 /// 3. If all steps succeed:
      49 ///    - All compensations are registered but never executed
      50 ///    - Saga completes successfully
      51 ///
      52 /// **Compensation robustness:**
      53 /// - If a compensation fails, it's logged but doesn't stop other compensations
      54 /// - All registered compensations will attempt to execute, even if some fail
      55 /// - The original error is rethrown after all compensation attempts
      56 ///
      57 /// **Use cases:**
      58 /// - **Multi-step operations**: Operations that span multiple services/databases
      59 /// - **Data consistency**: Ensuring data consistency across multiple steps
      60 /// - **Order processing**: Purchase → Payment → Inventory → Shipping
      61 /// - **User registration**: Create account → Send email → Initialize preferences
      62 /// - **Batch operations**: Multiple interdependent operations with rollback
      63 ///

     195 /// A single step in a saga with its associated compensation.
     196 ///
     197 /// A [SagaStep] represents an operation that can succeed and be undone.
     198 /// It consists of:
     199 /// - [name]: A descriptive label for logging and debugging
     200 /// - [execute]: An async function that performs the operation
     201 /// - [compensate]: An async function that undoes the operation
     202 ///
     203 /// **Type parameter [T]:**
     204 /// The generic type [T] represents the return type of [execute]. This value
     205 /// is passed directly to [compensate] if the step succeeds and later needs
     206 /// to be rolled back. This ensures type safety: you can't pass the wrong type
     207 /// to compensation.
     208 ///
     209 /// **Execution contract:**
     210 /// - [execute] must be a nullary function (takes no parameters)
     211 /// - If [execute] throws, the step is considered failed
     212 /// - [compensate] receives the return value from a successful [execute]
     213 /// - [compensate] should be idempotent or at least safe to call even if
     214 ///   partial execution occurred
     215 /// - If [compensate] throws, it's logged but doesn't prevent other
     216 ///   compensations from running
     217 ///
     218 /// **Example - Database transaction:**
     219 /// ```dart
     220 /// const insertUserStep = SagaStep<int>(
     221 ///   name: 'Insert User',
     222 ///   execute: () async {
     223 ///     final userId = await db.users.insert(userData);
     224 ///     return userId;  // Returns the new user ID
     225 ///   },
     226 ///   compensate: (userId) async {
     227 ///     // userId is type-safe - definitely an int
     228 ///     await db.users.delete(userId);
     229 ///   },
     230 /// );
     231 /// ```
     232 ///
     233 /// **Example - API call with side effects:**
     234 /// ```dart
     235 /// const createSubscriptionStep = SagaStep<String>(
